# دليل الإشعارات ونشر التطبيق على Google Play (بلي ستور)

> الشروط والسياسات تتغير؛ تحقق من صفحات Google Play Console الحالية قبل كل خطوة.

## 1) الطريقة المعتمدة: TWA بدل Capacitor
- التطبيق الحالي المبني بـ Capacitor (`mobile/build-apk.sh`) يفتح الموقع داخل WebView، و**إشعارات Web Push لا تعمل داخل WebView**.
- لذلك جهّزنا مسار **TWA** (تطبيق أندرويد يفتح الموقع عبر Chrome): الإشعارات تعمل، وهو مقبول في المتجر.
- إن بقيت على Capacitor فالإشعارات تحتاج Firebase (FCM) + `google-services.json` + إضافة `@capacitor/push-notifications`، وهي مرحلة منفصلة.
- **حدّ مهم:** TWA لا يتتبع موقع الكابتن والتطبيق مغلق/في الخلفية. تتبّع الكابتن والملاحة الصوتية يعملان والتطبيق مفتوح. إن احتجت التتبع في الخلفية فيلزم تطبيق أندرويد أصلي بخدمة موقع.

## 2) ما الذي أُضيف في المشروع
| الملف | وظيفته |
|---|---|
| `push.js` (جذر المشروع) | سيرفر الإشعارات (Web Push/VAPID) بدون مكتبات |
| `public/push.js` | يطلب إذن الإشعارات ويسجّل اشتراك الجهاز |
| `public/sw.js` | يستقبل الإشعار ويفتح التطبيق عند الضغط |
| `public/manifest-*.webmanifest` | ملف التطبيق (زبون/كابتن/مطعم/جهاز المطعم) |
| `public/icons/` | أيقونات 192/512/maskable/Apple |
| `public/privacy.html` | رابط سياسة الخصوصية (مطلوب) |
| `public/delete-account.html` | رابط حذف الحساب (مطلوب) |
| `public/.well-known/assetlinks.json` | ربط التطبيق بالموقع (قالب تُعبّأ بصمته) |
| `store/twa-manifest.*.json` | إعدادات Bubblewrap للزبون والكابتن |
| `gen-vapid.js` | يولّد مفاتيح VAPID (`npm run vapid`) |

## 3) تفعيل الإشعارات (على Render)
1. شغّل محلياً: `npm run vapid` وانسخ المخرجات.
2. في Render ← Environment أضف: `VAPID_PUBLIC` و`VAPID_PRIVATE` و`VAPID_SUBJECT` (مثل `mailto:support@your-domain.com`).
   بدونها تُولَّد مفاتيح جديدة عند كل نشر إذا لم يوجد قرص دائم، فتضيع الاشتراكات.
3. اختبر على هاتف أندرويد (Chrome) عبر **HTTPS**: افتح التطبيق وسجّل الدخول، اضغط «تفعيل» في الشريط الأعلى.
4. أنشئ رحلة تجريبية: يصل الإشعار للكابتن عند تعيين الطلب، وللزبون عند قبول الرحلة ووصول الكابتن والانتهاء، وللمطعم عند وصول طلب جديد.
5. آيفون: يعمل فقط إذا أضاف المستخدم الموقع إلى الشاشة الرئيسية (iOS 16.4+).

الإشعارات الحالية: تعيين طلب للكابتن • قبول الرحلة/وصول الكابتن/بدء/انتهاء/إلغاء • زيادة الأجرة التلقائية • طلب جديد للمطعم • تحضير/جاهز/بالطريق/تسليم/إلغاء الطلب.

## 4) متطلبات حساب المطوّر
- حساب Google Play Console (رسم تسجيل لمرة واحدة) + توثيق الهوية.
- الحسابات الشخصية الجديدة قد يُشترط فيها **اختبار مغلق** بعدد مختبرين لمدة 14 يوماً قبل الإنتاج (كان 12 مختبراً وقت كتابة الدليل). حساب المنظمة قد يُعفى.
- الدومين على **HTTPS** ثابت (مثل `taxi.your-domain.com`).

## 5) بناء ملف AAB
**الأسهل — PWABuilder:** ادخل `pwabuilder.com`، ضع `https://YOUR-DOMAIN.com/customer.html` ← Package for stores ← Android ← أنشئ AAB ووقّعه، ثم نزّل الملف وبصمة التوقيع.

**أو Bubblewrap (سطر أوامر):**
```
npm i -g @bubblewrap/cli
mkdir customer && cd customer
cp ../store/twa-manifest.customer.json twa-manifest.json   # عدّل YOUR-DOMAIN.com
bubblewrap init --manifest=https://YOUR-DOMAIN.com/manifest-customer.webmanifest
bubblewrap build        # ينتج app-release-bundle.aab
```
كرّر للكابتن بملف `twa-manifest.captain.json`. معرّفات الحزم المقترحة: `com.safra.customer` و`com.safra.captain` — **لا يمكن تغييرها بعد النشر**، فاختر الأسماء النهائية الآن.

## 6) ربط الموقع بالتطبيق (Digital Asset Links)
1. ارفع الـ AAB إلى Play Console (Internal testing) وفعّل **Play App Signing**.
2. من Play Console ← Setup ← App signing انسخ **SHA-256 certificate fingerprint**.
3. ضعه في `public/.well-known/assetlinks.json` بدل النص الافتراضي، وأعد النشر.
4. تحقق: `https://YOUR-DOMAIN.com/.well-known/assetlinks.json` يفتح، ثم من أداة Digital Asset Links. إن لم تُضبط ستظهر شريط عنوان Chrome داخل التطبيق.

## 7) بيانات صفحة المتجر
| الحقل | القيمة |
|---|---|
| الاسم (حتى 30 حرفاً) | تكسي المتميز |
| الوصف القصير (حتى 80) | اطلب تكسي وطعام وتوصيل بأسعار واضحة وتتبع مباشر |
| الأيقونة | PNG 512×512 (جاهزة: `public/icons/icon-512.png`، يُفضّل شعار نهائي) |
| Feature graphic | 1024×500 (يجب تصميمها) |
| لقطات الشاشة | 2 إلى 8 لقطات هاتف (9:16) للطلب والتتبع والملاحة |
| سياسة الخصوصية | `https://YOUR-DOMAIN.com/privacy.html` |
| حذف الحساب | `https://YOUR-DOMAIN.com/delete-account.html` + رابط داخل التطبيق (أُضيف في «حسابي») |
| التصنيف | خرائط وملاحة / سفر، أو طعام وشراب |
النصوص الجاهزة: `store/listing-ar.md`.

## 8) نماذج Play Console
- **Data safety:** تجمع: الموقع الدقيق، الاسم، رقم الهاتف، سجل الطلبات، معرّفات الجهاز، الصور (اختيارية). مشفّرة أثناء النقل: نعم. لا تُباع لأطراف ثالثة. تُشارك مع الكابتن/المطعم لتنفيذ الخدمة. يمكن طلب الحذف: نعم.
- **App access:** المراجِع يحتاج دخولاً. جهّز حساب زبون وكابتن تجريبيين وأدخل بياناتهما مع تعليمات (الدخول بالهاتف قد يحتاج OTP: وفّر رمزاً ثابتاً للمراجِع أو حساب Google تجريبياً).
- **Content rating:** استبيان (لا محتوى عنيف). **Target audience:** 18+.
- **الموقع:** صرّح بأن الموقع مطلوب لوظيفة التطبيق الأساسية (طلب الرحلة). لا تطلب «الموقع في الخلفية» مع TWA.
- **المدفوعات:** الرحلات والطعام خدمات/سلع مادية، فلا يُشترط نظام الدفع داخل جوجل بلاي.
- **Ads:** لا إعلانات.

## 10) أسباب رفض شائعة
- تطبيق «مجرد موقع» بلا قيمة (Minimum Functionality): تجاوزناه بالإشعارات والتتبع والمحفظة، فاذكرها في الوصف.
- غياب سياسة خصوصية/حذف حساب أو عدم تطابق Data safety مع الواقع.
- عدم تمكين المراجِع من الدخول.
- أيقونة/لقطات مضللة أو تحمل علامات تجارية لجهات أخرى (مثل Waze/Baly).
